## 2026-07-25 - [Context-Aware Tooltips and Accessible Buttons]
**Learning:** Explaining exactly why primary buttons are disabled (e.g. empty prompt, loading repositories, quota limit exceeded) through dynamic, state-aware `title` and `aria-label` attributes prevents user confusion and makes the UI fully compliant with screen-reader accessibility expectations. Additionally, reusable wrapper elements (like `Btn`) must always forward custom properties (`...props`) to the underlying HTML element so utility attributes (like `title` or `aria-label`) can be added cleanly at implementation sites.
**Action:** When creating any button wrappers or custom interactive elements, ensure they spread `...props` onto the native button/element. Always add context-aware tooltips and ARIA descriptions to state-dependent inputs and buttons.

## 2026-07-26 - [Interactive Password Visibility and Input Accessibility]
**Learning:** For secure credential entries (like API Keys), providing a visual and keyboard-accessible "Show/Hide Password" toggle button significantly improves usability and reduces connection errors caused by transcription or copy-paste mistakes. Furthermore, associating a precise `aria-label` with the credentials input ensures that screen readers can convey the input's exact purpose without relying on adjacent textual visual elements.
**Action:** When designing credential input fields, always provide an interactive toggle to let users verify their inputs, ensure the text does not visually overlap the toggle icon by setting adequate right padding, and declare explicit ARIA label attributes for screen-reader clarity.
