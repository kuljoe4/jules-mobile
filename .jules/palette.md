## 2026-07-25 - [Context-Aware Tooltips and Accessible Buttons]
**Learning:** Explaining exactly why primary buttons are disabled (e.g. empty prompt, loading repositories, quota limit exceeded) through dynamic, state-aware `title` and `aria-label` attributes prevents user confusion and makes the UI fully compliant with screen-reader accessibility expectations. Additionally, reusable wrapper elements (like `Btn`) must always forward custom properties (`...props`) to the underlying HTML element so utility attributes (like `title` or `aria-label`) can be added cleanly at implementation sites.
**Action:** When creating any button wrappers or custom interactive elements, ensure they spread `...props` onto the native button/element. Always add context-aware tooltips and ARIA descriptions to state-dependent inputs and buttons.

## 2026-07-26 - [Interactive Password Visibility and Input Accessibility]
**Learning:** For secure credential entries (like API Keys), providing a visual and keyboard-accessible "Show/Hide Password" toggle button significantly improves usability and reduces connection errors caused by transcription or copy-paste mistakes. Furthermore, associating a precise `aria-label` with the credentials input ensures that screen readers can convey the input's exact purpose without relying on adjacent textual visual elements.
**Action:** When designing credential input fields, always provide an interactive toggle to let users verify their inputs, ensure the text does not visually overlap the toggle icon by setting adequate right padding, and declare explicit ARIA label attributes for screen-reader clarity.

## 2026-07-27 - [Universal Keyboard Focus Indicators and CSS Specificity Overrides]
**Learning:** Standardizing highly accessible `:focus-visible` styles ensures that keyboard navigators have immediate, high-contrast visual feedback on their focus target without causing aesthetic clutter for mouse/touch users. When a codebase utilizes inline React/HTML styles featuring `outline: "none"`, standard CSS rules will be overridden by inline styles. Declaring `:focus-visible` with `!important` overrides inline style specificity cleanly, ensuring absolute keyboard accessibility compliance (WCAG 2.4.7 Focus Visible) across a large existing frontend without refactoring dozens of nested components.
**Action:** To ensure robust keyboard navigation support, declare global `:focus-visible` CSS rules on interactive element tags (`button`, `input`, `textarea`, `select`, `a`) and ARIA interactive roles (`[role="button"]`, `[tabindex="0"]`) using `!important` to safely override legacy inline outline resets.

## 2026-07-28 - [Descriptive ARIA Labels for Icon-Only Interactive Controls]
**Learning:** In highly compact, mobile-responsive layouts, interactive buttons are frequently rendered as standalone icons (e.g. trash cans, plus signs, chevrons, or close "x" marks) with only visual tooltips via `title` attributes. While tooltips provide mouse-hover context, assistive technologies like screen readers rely heavily on dedicated `aria-label` declarations. Without standardizing descriptive labels, these icon-only buttons remain entirely unlabelled in screen-reader navigation hierarchies, presenting a critical WCAG accessibility gap.
**Action:** Always pair `title` tooltips on interactive icon-only elements with an equivalent or superior `aria-label` matching the visual intent of the control, ensuring identical semantic context for keyboard/assistive navigators.

## 2026-07-29 - [Seamless Global Search Keyboard Shortcuts and Multi-tiered Escape Handling]
**Learning:** Integrating page-level hotkeys (like forward slash `/` to focus search) drastically elevates the power-user desktop feel, but must be paired with safety guards checking `document.activeElement` to prevent capturing inputs while typing in other forms. Additionally, implementing contextual Escape keydown handling (where first Escape clears query content, and the second collapses the panel) provides intuitive keyboard navigation. Finally, implementing Escape listeners on search dropdown fields (like repository and branch search pickers) mirrors the mouse backdrop-click behavior cleanly, creating a unified and delightful multi-tiered escape workflow.
**Action:** When creating searchable list views or dropdown pickers, always map global slash `/` shortcuts safely and bind context-sensitive `Escape` handlers to let keyboard users navigate, clear, and collapse panels seamlessly.

## 2026-07-30 - [Lifting Credentials State in Tabbed Settings & Broken Icon Prevention]
**Learning:** Moving configuration values (like API keys) from direct LocalStorage mutations within subcomponents to parent React state hooks ensures that changes instantly synchronize across background loops and network modules. Additionally, isolating primary setup parameters (like keys) into their own dedicated, discoverable tab (matching external providers' `Settings -> API` hierarchies) prevents visual clutter on general configuration pages. Finally, validating visual assets (e.g. replacing broken `'eye-off'` with mapped `'eye_closed'` keys) protects high-traffic credential fields from blank or corrupted icons.
**Action:** Always lift critical credential states to parent boundaries to keep network adapters synchronized, organize keys into dedicated tabs for maximum discoverability, and verify that icons mapped on password/key toggle inputs reference existing visual paths.

## 2026-07-31 - [Explicit ARIA Labeling on Character and Icon-Only Close Controls]
**Learning:** Visual-only symbol characters (like '×') or standalone icon tags (like `<Ic n="x" />`) used for closing modal sheets or dismissing persistent setup banners are completely opaque to screen readers or announced inappropriately (e.g., as "multiplication sign"). Providing explicit and distinct `aria-label` and `title` attributes (e.g., "Dismiss banner" and "Close Preview") is crucial to ensure identical semantic clarity and accessibility compliance across assistive device hierarchies.
**Action:** When defining dismissal triggers, overlay close banners, or custom media popup controllers, always attach highly precise 'title' and 'aria-label' attributes directly on the outer clickable elements to satisfy WCAG 2.1 accessibility criteria.
