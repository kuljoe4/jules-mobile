## 2026-07-24 - Algorithmic O(N^2) Over-rendering and Reference Stability Anti-pattern
**Learning:** In list-heavy React architectures (like `SessionList`), calculating item-specific relationships (like "drift" across all sessions) inside individual items leads to O(N^2) work on every single render. Moving aggregations to the parent level via `useMemo` reduces complexity to O(N) and keeps lookups constant-time O(1) inside items. Furthermore, wrapping a component with `React.memo` is completely bypassed if fallback props evaluate to a new reference on every render (such as `activitiesMap[s.id] || []` or inline closures like `onPress={() => onSelect(s)}`).
**Action:** Always pre-aggregate list statistics at the parent/store level. Use a custom `areEqual` comparator in `React.memo` to explicitly ignore recreated inline closures, and replace default inline empty object/array fallbacks (`|| []`) in prop mappings with module-level constants (e.g. `EMPTY_ARR = []`) to preserve reference stability and prevent unnecessary re-renders.
